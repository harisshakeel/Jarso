Both packages expose fixed subpaths through `exports` in [packages/core/package.json](packages/core/package.json) and [packages/data/package.json](packages/data/package.json). `data` depends only on `core`, `db` and `supabase-js`, and `core` only on `content`, `db` and `zod`. pnpm's isolated linker therefore makes `import "react"` fail to resolve even if the lint rule were skipped. The prose version of all this is [docs/architecture.md:190-197](docs/architecture.md#L190-L197).

## Where Biome enforces it ([biome.json](biome.json))

- **[biome.json:83-131](biome.json#L83-L131)**: the main override, covering `packages/core/**`, `packages/content/**` and `packages/data/**`.
  - `noRestrictedGlobals` ([88-101](biome.json#L88-L101)) blocks `window`, `document`, `navigator`, `localStorage`, `sessionStorage`, `indexedDB` and `location`.
  - `noRestrictedImports` ([102-127](biome.json#L102-L127)):
    - by exact name: `react`, `react-dom`, `server-only`, `@supabase/ssr`, `idb`
    - by pattern: `next` and `next/**`, `@/**` (the web app's aliases) and `@jarso/brand`
- **[biome.json:132-170](biome.json#L132-L170)**: `core/src/lib` and `core/src/config` repeat that list and also can't import any feature (`@jarso/core/**` except `lib` and `config`).
- **[biome.json:171-226](biome.json#L171-L226)**: the leaf modules (`ledger`, `goals`, `rules`, `profiles`, `auth`, `payments`, `allowance`) also can't import the composite modules (`learning`, `diary`, `requests`, `family`, `notifications`, `guide`, `review`, `offline`).
- **[biome.json:237-270](biome.json#L237-L270)**: going the other direction, web and mobile can't import `@jarso/core/lib` directly. They use `@/lib`, which sets up each app's logger.

The later overrides repeat the whole framework list on purpose. When two overrides set the same rule, Biome takes the later one's options rather than combining them, so leaving the list out would drop the React/Next ban for `lib`, `config` and the leaf modules.

## Gaps worth knowing

1. **No purity tests.** Rule 18 in CLAUDE.md says "Biome enforces this; tests in `packages/core/tests/` and `packages/data/tests/`". Those folders hold normal unit tests, plus a fake Supabase client at [packages/data/tests/fake-client.ts](packages/data/tests/fake-client.ts). Nothing in them scans imports. 2. **`@supabase/ssr` and `idb` are banned for `core` and `content` too**, not just `data` as CLAUDE.md says. That's stricter, so it does no harm.

4. **Composite modules can import each other in a loop.** Nothing stops a cycle among them, and [docs/architecture.md:191](docs/architecture.md#L191) says reviewers check this by hand.
