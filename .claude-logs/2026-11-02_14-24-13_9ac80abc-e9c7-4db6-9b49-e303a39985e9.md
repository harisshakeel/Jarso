I added a "Built to grow" section to the spec at `docs/superpowers/specs/2026-11-02-monorepo-shared-core-design.md`. These rules keep the structure clean as the codebase gets bigger, and tooling enforces them where it can:

1. **Dependencies only point one way.** Apps can depend on packages, never the reverse. If code imports a package it hasn't declared, pnpm fails it, and Biome blocks `@/*`, React, Next and server code inside core.
2. **Core is layered.** The bottom layer (`lib`, `config`) imports no feature code. Leaf features sit above it, and combined features (`review`, `learning`, `diary`, `notifications`) above those. Imports always go through a module's public path, and Biome blocks imports that point upward.
3. **A feature keeps the same name everywhere.** For example, `goals` lives at `packages/core/src/goals`, `apps/web/src/features/goals`, and later `apps/mobile/src/features/goals`. The `new-feature` skill will scaffold the core module first.
4. **Platform-specific code sits behind interfaces.** When core needs storage, network or locks, it defines an interface and each app supplies its own version. The offline outbox is the first example.
5. **Builds and tests are cached per package.** A change that only touches web doesn't re-run core's tests, and the reverse. CI checks only the packages a PR affects.
6. **There's a clear trigger for splitting core.** It stays one package until a module needs its own dependency, needs its own release, or core's tests take longer than about 60 seconds. Because each module already has its own import path, splitting one out won't break much.
7. **Tests live with their package.** Core's tests run without a browser environment, so they stay fast as they grow.

**`src/lib/api/index.ts`:**
- `withApi(handler, {crossOrigin?})` runs `assertSameOrigin`, a CSRF check. It applies only to non-GET requests that send an `Origin` header; requests without `Origin` pass.
- It maps errors:

  - `AppError` → `error.status`, with `{code, message, details: fieldErrors}`.
