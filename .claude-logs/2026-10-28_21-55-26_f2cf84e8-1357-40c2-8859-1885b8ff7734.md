The design spec for the first milestone is ready for you to read: [docs/superpowers/specs/2026-10-28-first-milestone-design.md](docs/superpowers/specs/2026-10-28-first-milestone-design.md). It is not committed yet, and we're on `main`.

A reviewer read it as if they had to build from it and raised six questions. You answered four, and these changes went in:
- **Deposits** are now in slice 4. They are a first-milestone acceptance criterion in REQUIREMENTS.md, so leaving them out was my mistake.
- **Demo clock:** each family gets a time offset that its parent can move forward, so judges can watch allowances fall due and reminders fire live. It is off unless both an environment flag and a per-family flag are set. Every time-based function takes an injectable "now" from slice 2 onward.
- **Several children per parent:** parent screens are scoped by child, with a child switcher.
- **Invites work without email:** each invitation gives a copyable link and a short code. Email is sent as well once Resend is configured.

Calls I made that you should check while reading:
1. **Child-started onboarding:** the child gets no account until the parent accepts. Until then the child sees a "show this to your parent" screen with the link and code. The form is rate-limited.
2. **Existing family:** if the accepting parent already has a family, the child joins it.
3. **Currency:** one per family, picked when the family is created. Currencies with no decimal places, like JPY, are supported.
4. **Time zone:** each family has a time zone, set from the browser. Limit weeks run Monday to Sunday and months are calendar months, both in that time zone.
5. **Due dates on the 29th–31st** move to the last day of shorter months.
6. **Deposits** never take Spend below zero, even when the parent allows overspending.
7. **Demo parents** are created by the seed script, because Supabase's built-in sign-up email is heavily rate-limited.
