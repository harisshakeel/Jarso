Inbox now updates live, using WebSockets through **Supabase Realtime**. A WebSocket server can't run inside Next.js on Vercel, but Supabase Realtime is a hosted one the project already had, so no new service or dependency was needed. Unit checks, build and all 89 Playwright tests pass, including a new one for the live update.

**What changed**
- **Migration** `20261031044405_notifications_realtime.sql`: adds `notifications` to the `supabase_realtime` publication. No new policies. Realtime checks each change against the existing select policy, so a user only gets their own notices.
- **`src/features/notifications/realtime.ts`**: `subscribeToNotices()` listens for new notices and read-state changes for the signed-in user only.
- **`components/notice-listener.tsx`**: when a notice arrives or changes, it refreshes the page so the Inbox badge, the inbox and "Needs you" redraw from the server. Several changes close together cause one refresh. New notices also show a toast with an **Open** button that goes to the inbox. If the connection drops and comes back, it refreshes once to catch up.
- **Parent and child layouts**: mount the listener inside `<Suspense>`. If anything fails, the app works as before, with the count updating on navigation.
- **Docs**: `architecture.md` §8, `database.md`, and the inbox spec (marked the "no realtime" decision as superseded).

**Bug found during testing:** the first live test failed. The browser joined the Realtime channel before the user's session token had loaded, so Supabase treated it as signed out and rejected the subscription. The fix sets the token before subscribing.

**Tests**
- Unit tests for the listener and for converting incoming rows.
- New Playwright test: a notice inserted on the server shows the toast, updates the badge and adds the inbox row, with no reload.

**Limitation:** incoming live events don't include the child's name, so a parent's toast says "Your child asked to add money to Save". The inbox row itself shows the name once the page refreshes.

**Before you ship**
- Nothing is committed yet. Everything is on branch `feat/inbox-realtime`.
- The hosted database needs the migration: run `pnpm db:push`.
- Realtime has to be enabled on the hosted Supabase project.

Realtime is already on for hosted Supabase projects, so this page has nothing to turn on. Don't click **"Set up realtime for me"**. It asks the dashboard's AI assistant to create things, and the migration already does what's needed.

Steps:

**1. Check that public channels are allowed**
- Left sidebar → **Configuration → Settings**.
- Find **"Allow public access"** (or a similarly named switch for public or private channels) and make sure it's **on**. On is the default.
- This matters because the app joins a public channel (`private: false`). Security doesn't depend on this switch: the table's own access rules still limit each user to their own rows.

**2. See which migrations production is missing**

In the repo terminal, run:
```
! supabase migration list --linked
```
Check the **Remote** column: `20261031044405_notifications_realtime` should be the only one blank. If other migrations are blank too, they'll go out in the same push. Make sure that's what you want.

**3. Apply the migration to production**
```
! pnpm db:push
```
This only adds the `notifications` table to the list of tables Supabase streams. It doesn't change any data, policies or permissions. If you'd rather, I can run it for you once you confirm.

**4. Confirm it took effect**

Dashboard → **SQL Editor**, run:
```sql
select tablename from pg_publication_tables where pubname = 'supabase_realtime';
```
You should see `notifications`.

**5. Deploy the code**

Merge `feat/inbox-realtime`, and Vercel deploys it. No new environment variables are needed: the existing Supabase URL and public key cover Realtime.

**6. Test it live**
- Sign in as a parent in one browser and as their child in another.
- Have the child send a request to add money to Save.
- The parent should get a toast and the Inbox badge should go up, with no reload.

If the toast doesn't show:
- Open DevTools → **Network → WS**, click the `realtime/v1/websocket` connection and read its messages.
- `"Subscribed to PostgreSQL"` means it worked.
- An error message there usually means step 1 or step 3 was missed.
