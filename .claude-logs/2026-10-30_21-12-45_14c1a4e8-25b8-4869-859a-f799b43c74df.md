The research agent has reported back. It didn't verify everything it set out to check (notes at the end). Here are the main findings and what they change:

**What the evidence says**
- **Put one next step first.** Duolingo rebuilt its home screen around a single guided path because learners didn't know which step to take next ([blog](https://blog.duolingo.com/new-duolingo-home-screen-design/)). This supports the "Do this next" card.
- **Show balances right under it.** Every kids' money app checked (GoHenry, Greenlight, Rooster Money, Revolut <18) is built around the balance.
- **Make the goal the child's own.** Rooster Money lets a child add a photo and a colour to a goal ([source](https://roostermoney.com/savings-pots-insights-2025/)). No study favours a ring, a bar or a road for this age group, so the plain bar is fine.
- **Streaks hurt kids.**
  - A 2026 study of children aged 6–12 using Duolingo found their goal turned into "keeping the streak", with "streak panic" at bedtime ([IDC 2026](https://dl.acm.org/doi/full/10.1145/3773077.3806127)).
  - The UK ICO children's code says children should be able to take breaks "without losing their progress" ([Std 5](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/childrens-information/childrens-code-guidance-and-resources/age-appropriate-design-a-code-of-practice-for-online-services/5-detrimental-use-of-data/)).
- **Avoid:**
  - losing lives on a wrong answer (Greenlight);
  - points that turn into gift cards (Zogo);
  - goal confetti (Greenlight);
  - "don't miss out" wording.

**Changes I'd make to the mockup**
1. **Drop the Mon–Sun day blocks.** Grey empty days still read like a streak. Instead show progress that only goes up: "3 skills learned · 2 missions this week", with skill chips that stay earned for good.
2. **Goal gets an emoji or photo** the child picks, next to the name.
3. Everything else stays as it is: next step first, money second, plain bar with "£19 to go, about 5 more allowances".

**Not verified:** what sits at the top of each money app's home screen, and the apps BusyKid, Step, Acorns Early, Till, Monzo teen, Osper, Khan Academy Kids and Prodigy.

- **ICO Children's Code, Standard 5:** names "reward loops… notifications" as sticky features. 1. **"Mark all as read" sends the user to the error page when offline or the connection drops.** `src/features/notifications/components/inbox-list.tsx:48-53`
   - **What:** `markAll` awaits `markNoticesReadAction` inside an async `startTransition` with no catch. Offline, the server action rejects with a TypeError. React 19 sends errors thrown inside a transition to the nearest error boundary, so a child tapping the button on a bad connection loses the page.
   - **Why it matters:** `docs/architecture.md:604` sets the convention that online-only actions go through `runOnline` (`@/features/offline`), and about 20 call sites follow it.
   - **Fix:** `const result = await runOnline(() => markNoticesReadAction(null, { ids: null }));`. The existing `toast.error(result.error.message)` then shows the calm offline or slow copy.

2. **The badge goes stale during in-app navigation, which contradicts spec §4.1.** `src/app/(app)/child/layout.tsx:21,32`, `src/app/(app)/parent/layout.tsx:16,24`
   - **What:** Spec §4.1 (line 71) says the count "refreshes when the user navigates". The count lives in a layout, and layouts don't re-render on client navigation (`node_modules/next/dist/docs/01-app/03-api-reference/05-config/01-next-config-js/staleTimes.md:35`). It updates only on a full load, `router.refresh()`, or a server action that revalidates.
   - **Effect:** If a parent has the tab open when the cron or a child's over-limit purchase creates a notice, the badge doesn't move until they reload or do something. Worse, they can open `/parent/inbox`, see unread rows, and the badge still shows the old count. The e2e misses this because it uses `page.goto`.
   - **Fix (pick one):**
     - Cheapest: a small client effect in the nav that calls `router.refresh()` on `visibilitychange` to visible and when the pathname enters an inbox route.
     - Or accept the behaviour and change the spec/fr-audit wording to "refreshes on load and after reading".
   - Either way the gap should be decided, not left silent.
