Supabase has no "down" migrations, so you undo it by hand in two steps. Both run against production.

**1. Reverse the SQL.** Run this in the Supabase dashboard's SQL editor for the hosted project:

```sql
begin;
drop function if exists public.allowance_schedule_auto_charge(uuid);
revoke select on public.allowance_schedules from authenticated;
grant select on public.allowance_schedules to authenticated;
commit;
```

The last line puts back the table-wide read the old code needs. Leave out `anon`: before the migration, `anon` had no table-level SELECT either, so the revoke in the migration didn't change anything for it.

**2. Tell Supabase the migration is no longer applied:**

```
! pnpm exec supabase migration repair --status reverted 20261101230000 --linked
```

After both, `supabase migration list --linked` should show `20261101230000` as local only, and the live app's schedule reads work again.
