The connection URL (`postgresql://postgres...`) isn't what the app needs. The app talks to Supabase over its HTTP API, not straight to Postgres. You need three values from the dashboard.

## 1. App env (`.env.local`)

Go to Dashboard → **Project Settings → API Keys** (the project URL is also on the **Data API** page):

```bash
NEXT_PUBLIC_APP_URL=http://localhost:3000
NEXT_PUBLIC_SUPABASE_URL=https://<project-ref>.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
SUPABASE_SECRET_KEY=sb_secret_...
LOG_LEVEL=info
```

`<project-ref>` is the random id in the dashboard URL (`supabase.com/dashboard/project/<project-ref>`). It also appears in your connection string as `postgres.<project-ref>` or `db.<project-ref>.supabase.co`.

## 2. Push the schema to the hosted DB

The CLI uses the project ref and your DB password, not the URL:

```bash
pnpm exec supabase login
pnpm exec supabase link --project-ref <project-ref>   # prompts for DB password
pnpm db:push                                          # applies supabase/migrations → creates profiles + RLS
pnpm exec supabase gen types typescript --linked > src/types/database.types.ts
```

Don't put the connection string (it contains your DB password) in `.env.local`. Nothing in the app reads it. It's only useful for psql or GUI tools.

## 3. Auth redirect URLs

Go to Dashboard → **Authentication → URL Configuration**:

- **Site URL:** `http://localhost:3000` for now (your production URL later)
- **Redirect URLs:** add `http://localhost:3000/auth/callback`

Without this, email confirmation links won't land back in the app.

## 4. Run

```bash
pnpm dev
```

Go to `/signup` and create an account. A `profiles` row should appear in Table Editor, created by the signup trigger. Email confirmation is on by default in hosted projects, so confirm via the email before signing in.
