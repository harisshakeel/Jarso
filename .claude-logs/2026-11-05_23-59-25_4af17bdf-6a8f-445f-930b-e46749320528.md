**Jarso cheatsheet: how it's built**

**What it is**
- A pocket-money learning app for 11–14 year olds, with linked parent and child accounts.
- Kids have Spend and Save jars, an allowance, a goal, a money diary and 7 lesson missions. Jarso is an AI money guide.
- Built for a pilot of about 60 users, so it's deliberately kept simple: no microservices, no Redis, no queues.

**Stack**
- **Web:** Next.js 16 (App Router, with Server Components and Cache Components), TypeScript, Tailwind v4 and shadcn/ui, hosted on Vercel.
- **Phone:** an Expo (React Native) app that uses the same backend.
- **Backend and database:** Supabase, which provides Postgres, auth and row-level security.
- **AI:** Claude. Sonnet 5.5 answers chats, and Haiku 5.5 screens messages for safety first.
- **Payments:** Stripe and Razorpay, in test mode only.

**Monorepo (pnpm + Turborepo)**
- `apps/web`: the website and the API.
- `apps/mobile`: the phone app.
- `packages/core`: the pure business rules and all the wording, shared by web and phone.
- `packages/data`: the database queries, shared by web and phone.
- `packages/db`: the database types, generated from the schema.
- `packages/brand`: the design tokens and logos.

**How a request flows**
- Page or API → service (business rules) → repository (the only code that touches tables) → Supabase.
- Every input is validated with Zod.
- Web forms use Server Actions, and the phone uses versioned REST routes under `/api/v1/*`.
- Auth is checked on the server for every request. The redirects are only a convenience.

**Security**
- Every table has row-level security, so a parent sees only their own family and a child sees only themselves. This is enforced in Postgres itself, not just in app code.
- Children sign in with a nickname and PIN, and repeated wrong PINs lock the account. A child account can't set a real password; a database trigger scrambles it.
- Secrets live only in Vercel, never in the repo. The repo is public, so CI runs gitleaks and the session logs are redacted.
- Errors shown to users are always safe messages; raw errors never leak.

**Money rules**
- All amounts are stored as integers in the smallest unit (cents or paise), never as floats.
- Money is a ledger: every move is a row, and the jar balances are computed from those rows.
- Moving money between Spend and Save doesn't count as income.
- Practice money in lessons never mixes with real money.
- Learning progress is kept separate from money, so kids are rewarded for understanding, not for wealth.

**Allowance**
- A schedule (weekly or monthly) creates due handovers when they're needed.
- The parent hands it over by cash or card, and it splits into the jars.
- Allowances can be paused, stopped, matched or given as gifts.

**Learning**
- 7 missions, plus a starting check-in, spaced review of skills, and practice questions.
- Points and streaks are calculated from the answer records; there's no separate score to fake.

**Jarso (AI guide)**
- It uses Claude with tools, so it can read the family's data and prepare actions for the user to confirm.
- It remembers short facts a child shares. Names, places and amounts are removed before saving, and the child and parent can see and delete every fact.
- Spending on Claude is capped at US$100 a month.
- Chats that need attention are flagged for the parent.
- A weekly job sends parents a "Jarso noticed" summary.

**Notifications**
- Web push on the website, and native push on the phone via Expo and Firebase.
- Quiet hours are respected, and there's an in-app Notifications page.

**Offline**
- Actions taken offline go into an outbox and are sent when the connection comes back.

**Delivery**
- GitHub PR → CI checks (Biome lint, typecheck, unit tests, a build, Playwright e2e, secret scan, commit-message lint, CodeRabbit review) → squash-merge → Vercel deploys automatically.
- Database changes are SQL migrations, 59 so far. Supabase applies them only when a PR merges to main.
- Scheduled jobs on Vercel: card auto-charge daily, and Jarso noticed weekly on Sunday.

**Monitoring**
- `/api/health` checks that the server is up, and `/api/health?deep=1` also checks the database and the AI guide.
- Vercel logs show runtime errors, which is how we caught today's Stripe key problem.
- Today's lesson: the server checks its environment variables at startup, so one wrong value on Vercel can take the whole backend down.
